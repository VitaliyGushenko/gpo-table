# Отладка фронта is_nsi

Правило №1: **лечить причину, а не симптом.** Подавить ошибку `?`, `catch` без обработки или `as any` — не фикс, а перенос бага в менее предсказуемое место.

## Процесс

1. **Воспроизведи.** Стабильно повторяющийся сценарий — половина диагноза. Воспроизводит пользователь: агент браузер не открывает и dev-сервер не запускает. Если не воспроизводится — уточни окружение (test/prod-конфиг, роль, версия) и шаги.
2. **Собери факты, не гипотезы:** текст ошибки, присланный пользователем (консоль, Network, Sentry), точное место в коде. Стек с tracekit может указывать в бандл — находи реальный файл по сообщению и последнему проектному фрейму.
3. **Локализуй сужением:** по коду — от точки входа (компонент, шаблон) к методу и выражению; для UI смотри шаблон, импорты модулей и директив, стили и их наследование.
4. **Назови причину одной фразой** («state-сервис не снял isLoading в finally при ошибке второй вкладки») — только потом правь. Если одной фразой не получается — диагноза ещё нет, копай.
5. **Фикс — минимальный** и по классификации скилла `architecture` (багфикс не смешивается с рефакторингом). После — проверь воспроизведение: сценарий из шага 1 должен пройти, смежные — не сломаться.

## Инструменты

- **Только код и присланные факты.** Браузер и dev-сервер — не инструменты агента: страницу открывает и сценарий воспроизводит пользователь, он же присылает текст ошибки консоли, Network и Sentry. Конфигурации запуска для пользователя — скрипты `start:*` в `package.json` (доменно-зависимые, например proplan/balance).
- **Консоль браузера** — первый источник для ошибок шаблона (strictTemplates), зон (zone.js) и HTTP: проси у пользователя текст ошибки и последний проектный фрейм стека.
- **Sentry** — `SentryErrorHandler.sendSentryMessage` (`src/app/utility/Sentry.ts`) пишет в консоль и на сервер; если баг с прод/test — попроси событие Sentry или его текст.
- **Сеть** — вкладка Network на стороне пользователя: статус, payload и тело ошибки (GraphQL кладёт человекочитаемое сообщение в `graphQLErrors[0].message` — его же показывает `Utils.getTextError`).

## Типовые причины в этом проекте

Проверяй по порядку «дешёвое — дорогое»:

1. **Несвежий кодоген.** Изменилось API/схема, а `@swagger/api` или `graphql/types` не регенерированы: типы не совпадают, «пропали» поля. Проверка: `npm run verify:codegen`; регенерация: `npm run swagger` (или `swagger:docker` без локального бэкенда), `npm run gql-build:<модуль>`.
2. **OnPush + мутация.** Данные изменились, представление — нет: мутировали объект из `@Input()` или объект внутри сигнала вместо `.set()` нового значения.
3. **Кэш Apollo.** Запрос вернул старое: у запросов проекта обычно `fetchPolicy: 'no-cache'` — если запрос новый и данные «не обновляются», проверь fetchPolicy и `refetch`/`watchQuery` сценарий.
4. **Ошибка шаблона, невидимая для tsc.** `npx tsc --noEmit` не проверяет шаблоны (strictTemplates — только `ng build`/dev-сервер): «странное» поведение без ошибок TS ищи в шаблоне (импорты модулей и директив, `@if`, привязки); консоль браузера — по тексту от пользователя.
5. **Гонки и повторные клики.** Второй клик до ответа, поздний ответ затирает свежий, уход со страницы во время запроса. Лечение — блокировка кнопки на время запроса и снятие `isLoading` в `finally`.
6. **Права/режим просмотра.** Элемент «пропал» или «не нажимается»: `viewMode`, `canXxx()`, роли — проверь вычисление доступности в state-сервисе, а не в шаблоне.
7. **Легаси-гиганты** (`catalog.component`, `buy.service`, `nsi.service`): симптом часто проявляется далеко от причины — ищи потребителей общих сервисов поиском по методу.

## Правила

- Браузер не открывать и dev-сервер не запускать: причина ищется по коду, а воспроизведение, консоль и Network — на стороне пользователя.
- Не править наугад несколько мест «на всякий случай» — каждая гипотеза проверяется отдельно.
- Если после двух итераций причина не найдена — остановись, собери факты и обсуди с пользователем, а не перебирай варианты дальше.
- Найденное стоит знать заранее? Зафиксируй: обнови соответствующий скил (типовая причина — сюда, паттерн — в `dev`).
