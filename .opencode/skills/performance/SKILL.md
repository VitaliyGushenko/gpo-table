# Производительность в is_nsi

Правило №1: **сначала измерь и локализуй, потом меняй.** «Кажется медленно» — не диагноз. Воспроизведение и замеры в браузере — на стороне пользователя (агент браузер не открывает и dev-сервер не запускает): получи от него, что именно медленно (загрузка? отрисовка? реакция на ввод?), найди это место по коду и только тогда применяй механизм из этого скила. Оптимизация без измерения обычно ухудшает код без выгоды.

## Готовые механизмы проекта — используй существующее

Не изобретай своё, пока не проверено готовое:

- **Большие таблицы** — таблица `gpo-lib` (`lib-gpo-table`) с режимом виртуального скролла nz-table: передай `useVirtualScroll` (пример: `buy/pages/report/report-prices`). Серверный пейджинг уже встроен (`nzFrontPagination="false"` + `nz-pagination`, данные грузит родитель по `pageIndexChange`).
- **Длинные списки выбора** — `cdk-virtual-scroll-viewport` с параметрами проекта (`itemSize="67" minBufferPx="700" maxBufferPx="800"`) + `cdkVirtualFor`; примеры: `catalog.component.html`, `select-single-list` (с бесконечной подгрузкой `nextBatch`).
- **Тяжёлый Excel-экспорт** — Web Worker, не основной поток. Образцы: `projects/balance/components/table/excel.worker.ts`, `proplan/components/table/src/excel-worker.ts` (+ сервис-обёртка `TableExcelExportService.exportWithWorker()` с `terminate` в `finally`), `lib/highlight.worker.ts`.
- **Мемоизация производных данных** — `memoDictionary` (`components/advanced-search-rest/search-item.ts`): кэш по ссылке источника. Создана ради кейса «ленивые справочники порождают тысячи nz-option на каждый цикл проверки» — при похожем кейсе используй её, а не новый кэш.
- **Ленивая загрузка** — норма проекта: `loadChildren`/`loadComponent` во всех фичах. Новый маршрут — только лениво.

## Правила для нового кода

- `ChangeDetectionStrategy.OnPush` — всегда (в свежих модулях proplan/balance — 100% компонентов).
- `@for` — всегда с `track` (идентификатор строки, не индекс, если строки переиспользуются). Старые `*ngFor` при рефакторинге переводить на `@for … track`.
- Вычисления для шаблона — `computed`, а не метод в шаблоне (метод вызывается на каждый цикл проверки). Не порождать новые массивы/объекты в шаблонных выражениях и в геттерах.
- Производные от сигналов — сигналы (`computed`), не ручная синхронизация полей.
- Списки опций-справочников: если провайдер опций строит массивы на каждый вызов — кэшируй по ссылке источника (`memoDictionary`).

## Когда НЕ оптимизировать

- Нет измеримого симптома («на всякий случай», «планируется рост данных») — не оптимизируй.
- Список короче сотни строк — виртуализация не нужна, она усложняет код.
- Усложнение ради микровыигрыша (один лишний map на 20 элементов) — вредно.
- Легаси-«тормоза» вне задачи — зафиксируй и сообщи пользователю, не переписывай «заодно».

## Диагностика

- Медленная страница: по данным пользователя из вкладки Performance (что занимает цикл — скрипт/отрисовка/сборка) плюс по коду — счётчики строк/опций на странице.
- Медленная сборка/бюджеты: budgets в `angular.json` задраны (initial до 7 МБ) — реальный анализ бандла через source-map-explorer при необходимости (не установлен — согласуй добавление с пользователем).
