# Безопасность фронта is_nsi

Проект внутренний, но XSS-правила действуют всегда: **пользовательский ввод никогда не попадает в разметку как HTML.**

## innerHTML и санитизация

- `[innerHTML]` в проекте массово (50+ мест) — только для контента из своей БД (описания, комментарии), который чистит дефолтный санитайзер Angular. Для такого контента bypass НЕ нужен: пиши `[innerHTML]="data.comment"` без пайпов.
- **Пайпы-обходы** `sanitizer` (`src/app/pipes/sanitizer.pipe.ts`) и `safeHtml` (proplan) — это `bypassSecurityTrustHtml`, то есть отключение санитизации. Допустимо только осознанно: доверенный контент, который дефолтный санитайзер ломает (сгенерированный HTML, разметка описаний из БД). Недопустимо для чего-либо, что мог ввести пользователь.
- Новый обход (`bypassSecurityTrust*` любого вида) — редкость; если он понадобился, объясни в комментарии, почему контент доверенный.
- iframe/PDF: `SafePipe`/`bypassSecurityTrustResourceUrl` — только для внутренних доверенных URL (образцы: `mid/invest-programs`, `remnant/warehouse-stocks`).
- Markdown (ngx-markdown, модалка новостей) санитизируется библиотекой автоматически — не отключать (`disableSanitizer` не ставить).
- Подсветка поиска (`highlightLatinCharacters` → `[innerHTML]`) работает на дефолтном санитайзере — при изменениях не ослабляй.

## Токены и авторизация

- OAuth через angular-oauth2-oidc; хранилище токенов — `localStorage` (`provide: OAuthStorage, useValue: localStorage` в `app.module.ts`) — осознанный выбор проекта, не меняй его на другой без просьбы.
- Токены не логировать, не передавать в URL, не отправлять в сторонние сервисы (в т.ч. в Sentry).

## Sentry

- `sendSentryMessage`/`SentryErrorHandler` отправляет всё как есть, фильтров (beforeSend) нет. В сообщения и breadcrumbs не должны попадать: персональные данные пользователей, содержимое документов, токены, пароли. Ошибка — да; данные из неё — нет.

## Окна и ссылки

- `window.open(url, '_blank')` — всегда с третьим аргументом `'noopener,noreferrer'` (образец: `ntfy/src/Utils.ts`). В шаблонах внешние ссылки — `target="_blank" rel="noopener noreferrer"` (норма свежего кода, см. `plan-table-page.component.html`).
- Выгрузка CSV через `window.open(<url_getaway-эндпоинт>, '_self')` — принятый паттерн, не менять.

## Секреты

- Секретов во фронте быть не должно: конфиги (URL, DSN) — в `src/assets/config/app.settings*.json`, приходят с сервера. Поле `dummyClientSecret` в `environments/` — мёртвый рудимент, не копировать паттерн и не добавлять подобных.
- Новые npm-зависимости — только с согласия пользователя (правило скилла `dev`): в т.ч. потому, что каждая зависимость — поверхность атаки.

## На ревью

Встретил в diff: `bypassSecurityTrust*` без обоснования, `[innerHTML]` с пользовательским вводом на входе, токен/персональные данные в `sendSentryMessage`, `window.open(_blank)` без noopener — замечание P1 по формату скилла `review`.
