# Тексты интерфейса в is_nsi

Интерфейс на русском, i18n-фреймворка нет — тексты пишутся инлайн в шаблонах/коде. Формулировки — по устоявшимся паттернам проекта, не сочиняй свои варианты для типовых мест.

## Обращение и тон

- Обращение — «Вы» с заглавной в вопросах и подтверждениях: «Вы уверены, что хотите удалить этого пользователя?»; строчное «вы» — только внутри фразы («У вас нет прав доступа к странице»).
- Тексты понятны пользователю, а не разработчику: никакого жаргона, идентификаторов и «обработчик не вернул результат».

## Кнопки

- Инфинитивы: «Сохранить», «Отмена», «Закрыть», «Удалить», «Создать», «Добавить», «Отправить». Пара — всегда «Отмена» + действие («Сохранить»/«Создать» по контексту, `{{ isEdit ? 'Сохранить' : 'Создать' }}`).
- Занятая кнопка отражает процесс, не молчит: `{{ disabledSave ? 'Расчет...' : 'Сохранить' }}`.
- Подтверждение опасного действия: `nzOkText: 'Да', nzCancelText: 'Нет', nzOkDanger: true` либо «Удалить»/«Отмена».

## Подтверждающие модалки

- Вопрос прямо в заголовке: «Вы уверены, что хотите …?», «Вы действительно хотите …?» — преобладающий стиль; альтернатива — `nzTitle: 'Подтверждение действия'` + вопрос в контенте (массово в balance). В новой фиче выбирай один стиль и держи его.

## Пустые состояния

- `nz-empty` с `nzNotFoundContent="Нет данных"`; в таблицах gpo-lib — «Данные не найдены»; компактные списки proplan — «Список пуст». Формулировка «не найдено» (после поиска/фильтра) vs «нет данных» (вообще ничего) — предпочтительна, но не переинженерь: дефолт «Нет данных» подходит почти всегда.

## Сообщения об ошибках и успехе

- Ошибка запроса показывается пользователю через `Utils.showError(error, (text) => this._msg.error(text))` (вытащит человекочитаемое `message` из тела, включая GraphQL `graphQLErrors[0].message`); в proplan — `errorHandler` (`projects/proplan/utils/error.ts`) + `messageService.error(...)`. Не показывай сырой `error.message` браузера и HTTP-статусы.
- Текст ошибки — что случилось и с чем: «Произошла ошибка при загрузке контрагентов»; дефолт, если specifics нет: «Произошла ошибка».
- Успех — короткий `success`-тост: «Комментарий успешно изменён!». Не дублируй тостами каждый шаг — только завершение значимых действий.

## Даты и числа — только проектными способами

Локаль `ru` зарегистрирована глобально (`LOCALE_ID`, `registerLocaleData(ru)`), новые механизмы форматирования не изобретать:

| Что | Как | Пример |
| --- | --- | --- |
| Дата | `\| date: 'dd.MM.yyyy'` | `{{ data.createdAt \| date: 'dd.MM.yyyy' }}` |
| Дата и время | `\| date: 'dd.MM.yyyy, H:mm'` (дефолт gpo-lib) | логи, истории изменений |
| Полное время | `\| date: 'dd.MM.yyyy HH:mm:ss'` | журналирование |
| Число/сумма | `\| number: '1.2-2':'ru'` | цены, количества |
| Число в proplan | `\| decimalFormat` (precision, `isInput` для полей ввода) | расчётные таблицы |
| Счётчик записей | `\| numberPipe` | «Всего записей: N» в gpo-lib |
| Форматирование в TS | `Utils.numberRound`, `Utils.formatDate` | не писать своё |

- Единицы — в заголовке колонки, не в каждой ячейке: «Цена единицы, руб.».
- Месяц по номеру — пайп `monthNamePipe`; диапазон дат — `twoMonthsPipe`.
